# lottery-bot

동행복권 로또 6/45·연금복권 720+를 이 컴퓨터의 **cron + Rust 단일 실행 파일**로 구매하고, 텔레그램으로 구매 번호와 당첨 결과를 알려줍니다. 기존 Python 코드는 이관 참고용으로 남겨 두었으며 새 실행 경로에서는 사용하지 않습니다. GitHub Actions 설정은 제거했습니다.

| 작업 | 한국 시간 (KST) | 내용 |
|---|---|---|
| 구매 | 매주 월요일 19:00 | 로또 `COUNT`게임 + 연금복권 같은 번호 1~5조 5매 |
| 확인 | 매주 토요일 22:00 | 이번 주 목요일 연금복권·토요일 로또의 상세 결과 (웹 직접 구매 포함) |

기본 `COUNT=5`이면 매주 총 10,000원입니다. 예치금 충전은 기존처럼 직접 합니다. 컴퓨터가 꺼져 있던 시간의 구매를 뒤늦게 실행하지 않습니다.

## 설치와 실행

Linux, Rust/Cargo 1.88 이상, cron이 필요합니다. 서버 시간대는 `Asia/Seoul`이어야 합니다. 설치 도구는 UTC+09:00이 아니면 일정 등록을 거절합니다. 빌드된 실행 파일은 Python이나 브라우저 없이 동작합니다.

```bash
cp .env.sample .env    # 기존 .env가 있으면 이 단계 생략
chmod 600 .env
# .env의 USERNAME, PASSWORD, COUNT, TELEGRAM_WEBHOOK_URL 설정
make install
make doctor           # 외부 접속 없는 설정 확인
./bin/lottery-bot preflight  # 로그인·잔액·게임·내역 점검. 구매하지 않음
./bin/lottery-bot notify-test  # 설치 확인 텔레그램 알림 1회
make cron             # 이 컴퓨터에 실제 일정 등록
```

기존 `.env`와 Telegram `sendMessage` URL(`chat_id` 쿼리 포함)을 그대로 사용할 수 있습니다. URL의 토큰은 로그에 출력하지 않습니다. 프로세스 환경변수가 `.env`보다 우선합니다. 비밀번호에 `#`, 공백 등이 있으면 dotenv 형식에 맞게 따옴표로 감싸세요. `.env`를 셸에서 `source`하지 않습니다.

```bash
make status           # 로그인·잔액 조회
make buy              # 실제 구매
make check            # 이번 주 추첨 대상 재조회 및 텔레그램 알림 (매번 실행 가능)
./bin/lottery-bot notify  # 보관된 미전송 알림 전달 (동행복권 접속 없음)
crontab -l            # 설치된 일정 확인
make uninstall-cron   # 이 프로젝트의 일정만 제거
```

`--env /절대경로/.env`로 설정 파일을 지정할 수 있습니다. 모든 실행은 같은 프로젝트 디렉터리에서 같은 `STATE_DIR`를 사용하세요. `scripts/run-job.sh`는 작업 디렉터리를 고정하며 실행 시간을 15분으로 제한합니다. `make cron`을 반복해도 일정이 중복되지 않고, 기존의 다른 cron 작업은 보존됩니다. 등록 전 crontab 백업은 `.state/crontab.before.*`에 남습니다.

## 텔레그램 알림

제목·회차·결제 금액·잔액을 HTML로 강조하고, 번호는 고정폭 표로 정렬합니다. 이번 주(한국 시간 월요일~일요일) 추첨 대상인 회차만 확인하며, 조회 결과는 복권별 메시지로 묶어 전송합니다. 웹에서 직접 구매하거나 미리 구매해 둔 복권도 놓치지 않도록 계정의 최근 91일 구매내역을 조회한 뒤 해당 회차만 선택합니다. 동일한 주문의 연금복권 상세는 한 번만 조회합니다. 예를 들면 다음처럼 표시됩니다.

```text
🎟 로또 6/45 · 구매 완료

1234회 · 자동 5게임 · 5,000원

A │ 01  07  13  24  32  45
B │ 02  08  19  27  35  42
…

💳 남은 예치금 12,000원

────────────
🕒 10.19 19:00 KST
```

당첨 확인은 게임별 등수를 표시하고, 로또 당첨번호와 일치한 숫자는 `[07]`로 표시합니다. 추첨 전·결과 미반영·조회 실패를 낙첨과 구분합니다. 로그인 실패, 구매 결과 불확실, 403/429 등 예약 작업의 실패도 중단 알림으로 전송합니다.

알림은 `.state/state.json`의 발송함에 먼저 보관합니다. `make check`는 하루에 여러 번 실행해도 매번 새로 조회하고 알립니다. 각 실행에 별도 발송 ID를 부여하므로 평일 수동 확인이 토요일 정기 확인을 막지 않습니다. 같은 실행의 성공한 알림은 자동으로 반복 전송하지 않고, 텔레그램 429는 대기 시간을 저장합니다. 응답을 받지 못한 전송은 `unknown`으로 남겨 중복 메시지 재전송을 막습니다. 자동 알림 간격은 최소 3.1초입니다. 일시적 전송 실패가 다른 종류의 복권 구매를 막지 않습니다. 보관 중인 `pending` 알림은 다음 작업 또는 `notify` 명령에서 전송합니다.

## 요청 제한과 중복 구매 방지

- 모든 동행복권 도메인·리다이렉트에 **기본 5초 + 0.1~1초** 간격을 공통 적용합니다. `REQUEST_INTERVAL_SECONDS`로 5~300초 사이에서 늘릴 수 있습니다.
- 로그인은 실행당 한 번만 합니다. 로그인 페이지에 포함된 세션별 RSA 키를 사용하고, 없을 때만 별도 키 API를 호출합니다. 사이트의 비밀번호 변경 안내는 실제 ‘다음에 변경’ 버튼과 같은 JSON 요청으로 한 번 유예하고 로그인 완료를 확인합니다. 비밀번호 자체는 변경하지 않습니다.
- **403/429는 즉시 중단**합니다. 기본 1시간, 반복 차단은 2·4·8·16·32시간으로 대기 시간이 늘어나며, 서버 `Retry-After`가 더 길면 그 값을 따릅니다. 초 단위와 HTTP 날짜 형식을 모두 지원합니다. 상태가 디스크에 남으므로 프로세스를 다시 실행해도 대기를 무시하지 않습니다.
- HTTP 라이브러리 자체 재시도를 끄고, 타임아웃·5xx·구매 POST·주문 POST를 자동 재전송하지 않습니다. 대기열도 반복 조회하지 않습니다.
- 파일 잠금으로 구매·조회·수동 실행의 동시 접속을 막습니다. 요청 시각과 구매 상태는 권한 0600의 파일에 원자적으로 저장하고 디스크 동기화를 수행합니다.
- 로또와 연금복권별로 회차·주간 중복을 막고, 사이트 구매내역도 확인합니다. 다른 기기에서 이미 구매한 회차는 추가 구매하지 않습니다.
- 주문/구매 직전에 `pending` 상태를 기록합니다. 요청 중 종료·네트워크 단절·응답 오류가 발생하면 **구매 성공 여부가 불확실한 상태로 유지**하고 자동 재구매하지 않습니다.
- 로또 회차·추첨일·지급기한은 게임 페이지에서, 연금복권 회차는 게임 페이지의 조회 API에서 확인합니다. 읽지 못하면 중단합니다. 구매 회차를 달력으로 추측하지 않습니다. 당첨 확인의 주간 대상은 공식 주간 추첨 일정과 실측한 회차·추첨일 기준으로 정하고, 구매내역의 추첨일이 다르면 일정 변경 오류로 중단합니다. 구매내역 응답의 전체 건수를 검증하고 필요한 페이지를 순서대로 조회합니다 (최대 500건). 불완전한 자료로 구매 판단을 하지 않습니다.

`pending` 구매가 남으면 사이트의 구매내역을 먼저 확인하세요. 성공했다면 해당 상태를 `success`로 조정하고, 확실히 주문/결제가 없었던 경우에만 그 구매의 `week`·`round` 항목을 제거해 수동 재실행합니다. **상태 디렉터리를 통째로 삭제하면 중복 구매 방지 기록이 사라집니다.**

## 운영과 검증

로그는 `.logs/YYYY-MM.log`, 상태와 알림 발송함은 `.state/state.json`에 저장됩니다. 두 디렉터리는 권한 0700이며 Git에 포함되지 않습니다. 로그·발송함에는 구매 번호와 결과가 들어가므로 로컬 사용자만 읽을 수 있게 유지하세요.

```bash
make test
# cargo fmt --check, cargo test --locked,
# cargo clippy --locked --all-targets -- -D warnings
```

테스트는 로컬 가짜 HTTP 서버로 429 대기 상태의 재시작 후 유지, 503 재시도 금지, 구매 POST 리다이렉트 재전송 금지, 파일 잠금·구매 중복 방지, 암호화, HTML 이스케이프와 알림 발송함을 확인합니다. 테스트가 실제 복권을 구매하거나 동행복권·텔레그램에 접속하지 않습니다. 실제 결제 성공까지 검증하려면 예약 실행 결과와 사이트 구매내역을 함께 확인하세요.

최신 관련 프로젝트 조사와 적용 사항은 [docs/references.md](docs/references.md)를 참고하세요.
